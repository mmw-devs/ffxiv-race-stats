> 设计文档 | 保存于 2026-07-15

---

## 核心定位

**lark-bot 是 PI Agent 的飞书能力网关**——双向代理，不持有一行业务逻辑。

```
飞书用户 ←──→ lark-bot ←──→ PI Agent
              │
              ├── 消息通道：飞书消息 ↔ agent 对话
              └── 操作通道：agent → lark-cli → 飞书 API
```

## 模块交互关系

| 模块 | 交互方式 | 方向 |
|------|---------|------|
| **PI Agent** | IPC，bot 不启动 agent | 双向 |
| **`.pi/skills/*`** | 不直接交互。agent 通过 IPC 下发飞书操作指令 | agent → bot |
| **`@larksuite/cli`** | bot 的唯一飞书接口 | bot → 飞书 |
| **`lark-cli event consume`** | bot 启动的常驻子进程，WebSocket 监听飞书事件 | 飞书 → bot |
| **`public/data.json`** | 不直接交互 | — |
| **`src/`（前端）** | 不交互 | — |

## 职责边界

```
lark-bot 做：                        lark-bot 不做：
─────────────────────────────────    ─────────────────────────
• 启动/管理 event consume 进程       • 解析用户意图
• 接收飞书事件，提取结构化字段       • 匹配 skill / 路由分发
• 翻译飞书事件 → agent 可读消息      • 维护对话上下文
• 接收 agent 回复 → lark-cli reply   • 执行业务流程
• 执行 agent 下发的 lark-cli 命令    • 判断权限 / 校验参数
• 翻译 lark-cli 输出 → agent 可读    • 修改 data.json
```
