# 首届赛事骨架（C 方案）

首届不走 `ops-event` 的换届指令，由人工准备完整骨架；之后第二届起再使用 `ops-event`。

## 0. 使用方式与硬规则

- 一次性引导：赛事信息 + 站点内容 + 对外发布先准备，队伍等报名截止后加
- 报名期可先上线「预告页」：队伍为空，公告写“参赛名单确认中”
- **公开上线前不得出现占位队名、占位文案、空白素材**
- 所有修改走 `content/*` PR：校验 + 预览 + **人工合并（首届统一人工，不走 L2 自动合并）**
- 速报在赛前必须为空；赛前信息放公告

## 1. 待填信息

| 项 | 谁提供 | 备注 |
|---|---|---|
| 赛事名 | 赛事总控 | ≤16 字、不含标点 |
| 届次 | 赛事总控 | 首届 `01` |
| 副本形态 | 赛事总控 | 1 个（绝境）或 4 个（零式） |
| 开赛时间 | 赛事总控 | 北京时间；可先待定 |
| 预热时间 | 赛事总控 | 开赛前 10 分钟 |
| 队伍名单 | 报名结果 | 报名截止后确定 |
| 展示顺序 | 赛事总控 | 运营给什么顺序就写什么，无种子规则 |
| 赞助 / 转播台 | 商务 / 转播 | 逐条确认 |
| 首页文案 / 规则 / SEO | 宣发 / 赛事总控 | 简体中文、全角标点 |
| 视频 / 海报 | 设计 / 宣发 | 素材进 dev 仓库，ops 只写路径 |

## 2. 赛事信息

| 字段 | 必填 | 示例 | 说明 |
|---|---|---|---|
| `meta.eventName` | 是 | `阿卡迪亚零式 世界首杀竞速` | ≤16 字、不含标点 |
| `meta.edition` | 是 | `01` | 两位数字 |
| `meta.dungeons` | 是 | 4 个：`M1S`…`M4S` | 只能 1 或 4 个；名称含“零式”/“绝境” |
| `meta.startTime` | 否 | `2026-12-01T12:00:00Z` | 北京时间 20:00；未知用 `-` |
| `meta.status` | 是 | `upcoming` | 首届固定未开赛 |
| `meta.boss` / `dataCenter` | 否 | — | 预留字段，当前 UI 不渲染 |

副本示例（零式）：

```json
[
  { "id": "M1S", "name": "零式 1 层" },
  { "id": "M2S", "name": "零式 2 层" },
  { "id": "M3S", "name": "零式 3 层" },
  { "id": "M4S", "name": "零式 4 层" }
]
```

## 3. 队伍名单（报名截止后）

| 字段 | 要求 |
|---|---|
| 队伍数 | 报名结果决定，不预设 |
| 名次 | 1..N 连续；顺序由运营给，开赛后随进度重排 |
| 队名 | 显示宽度 ≤40；公开上线不允许占位 |
| 区服 | `JP / NA / EU / OC / CN / KR` |
| 初始阶段 | 第一层 `P1`（零式 `M1S-P1`；绝境 `P1`） |
| 初始血量 | 100 |
| 选手 | 恰好 8 人，顺序 2 坦 / 2 奶 / 4 输出 |
| 职业 | 官方三字母缩写，与位置对应 |
| 直播 | 无直播 `#` + `streaming=false`；有直播填链接 + `true` |

示例阵容顺序：

```
PLD WAR / WHM SCH / MNK DRG NIN BRD
```

注意：

- 数据里没有选手名，只有职业与直播链接
- 队伍 id 用 `t1…tN`，后续更新/退赛依赖它，不要复用
- 报名未截止时 `teams: []`，不要创建占位队伍

## 4. 对外发布

| 内容 | 要求 |
|---|---|
| `notices` | 至少 1 条、单条 ≤100 字、不重复；赛前信息放这里 |
| `news` | **赛前为空**（速报时间不得早于开赛） |
| `sponsors` | 名称 ≤20 字、描述 ≤100 字 |
| `broadcasters` | 名称 ≤20 且唯一、平台合法、链接域名匹配、备注 ≤60 |
| `content.rules` | 赛事规则属于站点内容，不是公告 |

赛前公告建议：

- 赛事时间与观看入口
- 参赛名单确认中 / 公布时间
- 赛制说明
- 数据由运营人工维护的说明
- 反馈/纠错渠道

## 5. 站点内容

| 字段 | 内容 |
|---|---|
| `content.hero.kicker` | 眉题 |
| `content.hero.lead` | 导语 |
| `content.hero.primaryCta` / `secondaryCta` | 按钮文案 + 链接 |
| `content.rules` | 标题、眉题、规则条目（至少 1 条） |
| `content.seo` | title、description、可选 ogImage |
| `content.media` | 视频与海报路径；素材在 dev 仓库 `public/` |
| `content.sections` | 四个已有章节的 kicker/title |

- 媒体使用带版本的文件名，避免 CDN 缓存旧素材
- 视频/海报合计控制在体积限额内
- SEO 是构建期快照，数据改完后需要触发一次 dev 构建

## 6. 空白骨架（结构示例，不可直接上线）

```json
{
  "meta": {
    "eventName": "<待填>",
    "edition": "01",
    "dungeons": [{ "id": "<待填>", "name": "<待填>" }],
    "startTime": "-",
    "status": "upcoming"
  },
  "content": {
    "hero": {
      "kicker": "<待填>",
      "lead": "<待填>",
      "primaryCta": { "label": "<待填>", "href": "#" },
      "secondaryCta": { "label": "<待填>", "href": "#" }
    },
    "rules": { "title": "<待填>", "kicker": "<待填>", "items": ["<待填>"] },
    "seo": { "title": "<待填>", "description": "<待填>" },
    "media": { "heroVideo": "/<待填>.mp4", "heroPoster": "/<待填>.jpg" },
    "sections": {
      "ranking": { "kicker": "<待填>", "title": "参赛名单确认中" },
      "news": { "kicker": "<待填>", "title": "<待填>" },
      "sponsors": { "kicker": "<待填>", "title": "<待填>" },
      "guides": { "kicker": "<待填>", "title": "<待填>" }
    }
  },
  "teams": [],
  "news": [],
  "broadcasters": [],
  "notices": ["<待填：赛前公告>"],
  "sponsors": []
}
```

说明：

- `<待填>` 会故意触发校验失败，防止误上线
- 报名期保持 `teams: []`；名单确定后再批量加队
- 如果先上线预告页，`content.sections.ranking.title` 写“参赛名单确认中”；名单确定后改回“实时排名”

## 7. 上线门禁

### 预告页（报名期）

- [ ] 赛事信息、站点内容、公告已填
- [ ] 队伍为空，榜单标题为“参赛名单确认中”
- [ ] 速报为空
- [ ] 预览正常，素材可加载
- [ ] 由有 GitHub 权限的人手动合并

### 完整上线（报名截止后）

- [ ] 真实名单，无占位队名
- [ ] 每队 8 人、位置顺序正确
- [ ] 名次 1..N 连续
- [ ] 开赛前全员第一层 P1 满血
- [ ] 速报为空、公告至少 1 条
- [ ] 预览通过；手动合并
- [ ] 预热时刻已排班

## 8. 执行顺序

```
报名期：赛事壳 + 站点内容 + 公告 → 预告页
报名截止：真实名单 + 展示顺序 → 完整预览
完整预览 → 手动合并
开赛前 10 分钟：预热上线（L3，人工合并）
开赛：发首条速报
结束：ops-event 结束赛事（L3，人工合并）
```

## 9. 校验

在 ops 仓库：

```bash
npm run validate
```

通过后创建 `content/*` PR；CI 会再次校验 schema、文件范围与操作日志。

## 10. 首届结束后

- 旧数据打归档标记：`archive/<届次>-<赛事短名>`
- 把本骨架固化为第二届的模板
- 第二届起使用 `ops-event` 的换届继承/重置规则；详见 `COMMANDS.md`
