# 运营指令目录（唯一来源）

> 本文件由 `contract/operations.json` 生成，请勿手改；修改契约后运行 `npm run contract:gen`。

本文件是运营指令的**唯一业务定义**：级别、确认强度、影响标记、前置条件、跨域交接。

- **数值、格式、结构规则不在本文件复述**；唯一来源是 `schema/*.json`、`scripts/validate-data.ts`、`shared/stage.mjs`。
- 业务域 skill 只负责识别指令、收集参数、展示预览和交接；**不得自行定义级别、合并方式或复述规则**。
- 所有写操作统一走 `ops-submit`。

## 1. 三级指令

| 级别 | 含义 | 合并方式 |
| --- | --- | --- |
| **L1** | 只读 | 无 |
| **L2** | 常规写 | 运行环境在操作者确认后合并；无合并能力则人工 |
| **L3** | 生命周期 | **只能人工在 PR 平台合并**；任何运行环境不得自动合并 |

- L3 只有：新建赛事 / 换届、预热上线、开赛（兜底）、结束赛事。
- 其他写操作一律 L2。

## 2. 确认强度

| 强度 | 操作者确认方式 |
| --- | --- |
| 普通 | 「确认」 |
| 短语 | 「确认名单调整」/「确认修改赛程」/「确认调名次」等 |
| 短语 + 原因 | 「确认修正」+ 原因 |
| 短语 + 人工合并 | 「确认开赛/结束/换届」→ 人工在 PR 平台合并 |

## 3. 影响标记

| 标记 | 含义 | 计算方式 |
| --- | --- | --- |
| `podium-change` | 前三名发生变化 | 按变更结果动态计算 |
| `final-standings-change` | 结束后最终名次/阶段变化 | 动态计算 |
| `schedule-change` | 开赛时间变化 | 指令固定 |
| `data-replacement` | 新建/换届替换数据 | 指令固定 |

影响标记只用于预览高亮与合并后提示，**不改变级别**。

## 4. 通用规则

1. 先读当前数据，再计算变更；不得凭记忆写值。
2. 变更必须字段级预览：旧值 → 新值、前置检查、名次影响、影响标记。
3. 本地校验不通过不得提交；提交后 CI 是第二道防线。
4. 同一时间只允许一个内容 PR；有未合并 PR 时拒绝新写指令并返回 PR 号。
5. 所有写操作必须记录审计：指令、操作人、时间、原因（修正类）、字段变更、影响标记；审计能力由运行环境提供，缺失时不得提交。
6. L3 创建 PR 后停止，不自动合并；必须由人工在 PR 平台合并。
7. 拒绝时给出下一步可执行指令，不只是报错。
8. 任何情况下不得直推 main。

### 4.1 运行环境适配

业务域 skill 与指令目录**不绑定消息渠道或 Agent 运行时**。

- 所有写操作统一交给 `ops-submit`；它只定义契约，不定义工具。
- 当前运行环境负责选择自己的适配器：
  - lark-bot → `ops-submit-larkbot`
  - DeepSeek Harness + mmw-tools → `ops-submit-dsh`
- 运行环境必须提供：稳定操作者身份、显式确认、审计、content PR、预览。
- 合并能力是可选的：L2 有则可在确认后自动合并，无则转人工；L3 永远人工。
- 任一能力缺失（身份/确认/审计/提交/预览）→ 拒绝写操作，不要临时拼命令。

## 5. 指令表

### 查询域（L1）

| 指令 | id | 说明 |
| --- | --- | --- |
| 查赛事状态 / 开赛时间 | `query.event-status` | 只读 |
| 查排名 | `query.ranking` | 只读 |
| 查某队进度 | `query.team-progress` | 只读 |
| 查某层剩余 / 谁没过 | `query.layer-remaining` | 只读 |
| 查直播覆盖 | `query.stream-coverage` | 只读 |
| 查待合并 PR / 冲突 | `query.pending-prs` | 只读，并提示下一步 |

查询不产生分支、不产生 PR；如果用户随后要求修改，交给对应业务域。

### 赛事域

| 指令 | id | 级别 | 确认 | 影响 | 前置条件 | 拒绝后下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| **新建赛事 / 换届** | `event.create-or-rotate` | L3 | 短语 + 人工合并 | `data-replacement` | 当前赛事已结束，或显式确认覆盖；旧数据已归档；模板完整 | 仍在进行 → 先结束，或显式覆盖 |
| **设置 / 修改开赛时间** | `event.schedule-set` | L2 | 短语 | `schedule-change` | upcoming；或 live 且全员仍在第一层 P1 | 已开打 → 不允许改时间 |
| **预热上线** | `event.preheat` | L3 | 短语 + 人工合并 | — | upcoming；全员第一层 P1 满血；开赛时间已设置且在未来 | 缺时间 → 先设置；已有进度 → 先修正 |
| **开赛（兜底）** | `event.start` | L3 | 短语 + 人工合并 | — | 同预热；已 live 则幂等 | 同上 |
| **结束赛事** | `event.end` | L3 | 短语 + 人工合并 | 动态 `final-standings-change` | live；当前数据构成合法最终快照（阶段/血量/名次合法） | 数据非法 → 先修正 |

说明：

- 开赛前 10 分钟预热；到达开赛时刻不需要再改数据，计时自然跨过 0。
- 结束是冻结当前战况，**不要求全员通关，也不把未通关队伍改成 CLEAR**。
- 首届赛事由人工骨架（C 方案）；本域的换届指令用于第二届起。

### 战况域

| 指令 | id | 级别 | 确认 | 影响 | 前置条件 | 拒绝后下一步 |
| --- | --- | --- | --- | --- | --- | --- |
| **更新进度** | `progress.update` | L2 | 普通 | 动态 `podium-change` | live；阶段/副本/血量合法；同层只能前进；跨层要求当前层 CLEAR；更新后名次与进度单调 | 未 CLEAR 跨层 → 先通关；超车 → 预览名次调整 |
| **批量更新** | `progress.bulk-update` | L2 | 普通 | 动态 `podium-change` | 同更新进度；全部变更原子应用 | 任一冲突 → 全部不写，列出冲突 |
| **通关** | `progress.clear` | L2 | 普通 | 动态 `podium-change` | live；目标当前在该层 | 已 CLEAR → 幂等 |
| **进入下一层** | `progress.next-layer` | L2 | 普通 | 动态 `podium-change` | 当前层 CLEAR；存在下一层 | 未 CLEAR → 先通关；最后一层 → 用通关 |
| **改血量** | `progress.set-hp` | L2 | 普通 | — | 同层；血量合法且不高于当前 | 血量归零 → 用通关 |
| **修正进度** | `progress.fix` | L2 | 短语 + 原因 | 动态 `podium-change` / `final-standings-change` | 阶段/血量合法；必须给原因；修正后名次单调 | 名次冲突 → 预览调整方案，确认后一并写 |
| **调整名次** | `progress.reorder` | L2 | 短语 | 动态 `podium-change` / `final-standings-change` | 名次连续；与进度单调 | 冲突 → 先修正进度 |

## 6. 跨域交接

| 场景 | 规则归属 | 交接 |
| --- | --- | --- |
| 新建赛事要创建队伍 | 名单域 | 赛事只建事件壳；队伍由名单域批量加 |
| 新建赛事要默认文案/公告 | 站点/发布 | 赛事调用两域模板，不自带文案 |
| 加减队要重排名次 | 战况域 | 名单调用战况的名次规则，不自己算 |
| 开赛要检查进度 | 战况域 | 赛事只读取校验结果，不重写规则 |
| 结束要冻结最终状态 | 战况域 | 赛事只改状态，快照合法性由通用规则保证 |
| 查询“谁没过某层” | 战况域 | 查询复用规则，不另写算法 |

## 7. 换届继承 / 重置

| 块 | 默认 | 说明 |
| --- | --- | --- |
| 赛事名 | 重填 | 必须新赛事名 |
| 届次 | 自动 +1 | 运营确认 |
| 副本列表 | 沿用待确认 | 换赛制时队伍清空重来 |
| 开赛时间 | 重填 | 可先待定 |
| 状态 | 固定 upcoming | 不继承 |
| 队伍 / 阵容 / 名次 / 进度 / 血量 / 直播 | 全部重置 | 报名后加真实队伍 |
| 速报 | 清空 | 旧速报会违反新时间线 |
| 公告 | 重写 | 旧日期会误导 |
| 赞助 / 转播台 | 沿用待确认 | 逐条确认 |
| 首页文案 / 规则 | 沿用待确认 | 赛事名/赛制可能变 |
| SEO | 重写 | 赛事专属 |
| 媒体 | 沿用或更新 | 无新素材用现有品牌素材 |
| 章节标题 | 沿用 | 一般不变 |

换届前给旧赛事打归档标记：`archive/<届次>-<赛事短名>`。

## 8. 常见拒绝与下一步

| 拒绝 | 下一步 |
| --- | --- |
| 赛前发速报 | 改用公告 |
| 未通关就进入下一层 | 先发「通关」 |
| 血量归零 | 用「通关」而不是改血量 |
| 加减队后名次冲突 | 交给战况域调整名次，或先修正进度 |
| 结束赛事时数据非法 | 先修正进度 |
| 已有未合并内容 PR | 先合并或等待，再提交新指令 |

## 9. 禁止

- 不静默继承队伍、成绩、速报
- 不把未通关队伍改成 CLEAR
- 不在 skill 里复述数值/格式/字段路径
- 不自行决定级别或合并方式
- 不直推 main
- 不修改 commit message 的结构化日志
- 不在 L3 自动合并
