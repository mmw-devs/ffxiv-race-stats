# ops-progress — 战况与名次

先加载 `COMMANDS.md` 的「战况域」；本 skill 只负责流程与话术。

## 职责边界

负责：

- 单队/批量更新阶段与血量
- 通关、进入下一层、改血量
- 修正进度、调整名次

不负责：

- 加队/删队/阵容（交给名单）
- 速报/公告（交给发布）
- 开赛/结束（交给赛事）

## 工作流

### 1. 解析目标与动作

支持：

- 「Alpha 到 M2S-P4，血量 42.5」
- 「批量：Alpha M2S-P4 42.5；Beta M2S-P3 60；Gamma M1S-CLEAR 0」
- 「Alpha 通关」
- 「Alpha 进入 M2S」
- 「Alpha 血量 30」
- 「修正：Alpha 应为 M1S-P4，血量 12，原因录错」
- 「把 Beta 调到第 2」

缺队伍、阶段或血量时只问缺的项。

### 2. 读取并校验

按 `COMMANDS.md` 的战况前置条件检查：

- 阶段/副本合法；同层只能前进，血量不高于当前
- 跨层必须当前层 CLEAR；进入新层血量重置
- 更新后名次与进度单调

**名次是战况域的唯一规则**：如果本次更新导致超车，必须同时计算并展示名次调整；不能只改阶段导致名次冲突。

### 3. 批量

一次说多队时：

- 先把所有变更算完
- 再统一做名次单调校验
- 任一项冲突则全部不写，列出冲突队伍和下一步

### 4. 修正

- 必须要求原因
- 允许回退和血量回升
- 展示“修改前 → 修改后”，以及是否触发 `podium-change` / `final-standings-change`
- 如果修正破坏名次单调，预览同时给出名次调整方案
- 确认用「确认修正」

### 5. 预览

展示：

- 队伍、阶段、血量的旧值 → 新值
- 受影响的名次变化
- 影响标记
- 前置检查结果

### 6. 记录并提交

- 把变更、指令和原因/影响交给 `ops-submit`；审计由当前运行环境的适配器生成
- 调 `ops-submit`，传 `command`（指令 id）与变更；级别由适配器查契约，不由本 skill 声明
- 普通进度用「确认」；调名次用短语；修正用「确认修正」+ 原因

## 拒绝模板

| 情况 | 下一步 |
|---|---|
| 未 CLEAR 就进入下一层 | 先发「通关」 |
| 血量填 0 | 使用「通关」，不要改血量 |
| 名次冲突 | 先修正进度，或在本次指令里一并调整名次 |
| 最后一层通关 | 用「通关」；是否结束由赛事域决定 |

```
【拒绝】Alpha 当前是 M2S-P3，不能直接进入 M3S。
下一步：先发「Alpha M2S 通关」，再发「Alpha 进入 M3S」。
```
