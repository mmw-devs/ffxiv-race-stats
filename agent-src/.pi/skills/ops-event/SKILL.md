# ops-event — 赛事生命周期

先加载 `.pi/commands.md` 的「赛事域」和「换届继承/重置」两节；本 skill 只负责流程与话术，不重复规则。

## 职责边界

负责：

- 新建赛事 / 换届
- 设置 / 修改开赛时间
- 预热上线 / 开赛（兜底）
- 结束赛事

不负责：

- 队伍、阵容、名次、进度（交给名单/战况）
- 速报、公告、赞助、转播台（交给发布）
- 站点文案/媒体（交给站点）

## 工作流

### 1. 识别指令与参数

| 指令 | 必需参数 |
|---|---|
| 新建赛事 / 换届 | 赛事名、届次、副本列表、开赛时间（可待定） |
| 设置 / 修改开赛时间 | 新时间（北京时间） |
| 预热上线 | 无；确认开赛时间已设置 |
| 开赛（兜底） | 无 |
| 结束赛事 | 无 |

缺参数时只问缺的那一项，不要一次问一长串。

### 2. 读取当前状态并校验

按 `.pi/commands.md` 的前置条件检查，向运营展示：

- 当前状态、开赛时间
- 前置检查结果（逐项 ✓ / ✗）
- 将发生的状态转换
- 对前端的直接影响

**结束赛事**只检查“当前数据是否构成合法最终快照”，**不要求全员通关，也不把未通关队伍改成 CLEAR**。如果数据非法，列出需要先修正的队伍，交给战况域。

**预热上线**检查全员是否仍在第一层 P1 满血；不满足则交给战况域修正，不能强行预热。

### 3. 换届

按 `.pi/commands.md` 的继承/重置矩阵生成草稿：

- 赛事信息重填
- 队伍清空
- 速报清空
- 公告重写
- 赞助/转播/文案/规则/媒体标记为「沿用待确认」

展示「沿用 / 重置 / 待确认」三类的字段级差异；确认旧数据已归档后再进入提交。

首届赛事由人工骨架（C 方案），不使用本域的换届指令；流程与字段清单见 `.pi/ops/first-event.md`。本域从第二届起使用。

### 4. 确认

- 预热 / 开赛：「确认开赛」
- 结束：「确认结束」
- 新建 / 换届：「确认换届」
- 修改开赛时间：「确认修改赛程」

### 5. 记录并提交

- 把字段变更、指令和原因/影响交给 `ops-submit`；审计由当前运行环境的适配器生成
- 提交通道创建 PR 后停止；L3 提示人工在 PR 平台合并

## 关键业务规则

- 预热提前 10 分钟；预热后前端显示 LIVE 并开始 60 秒同步
- 到达开赛时刻不需要再改数据；如需对外播报，交给发布域发速报
- 预热后、全员仍 P1 时可改开赛时间；一旦有进度则锁定
- 结束是冻结战况，不是批量通关
- 结束/开赛/换届只能人工合并，任何运行环境不得自动合并

## 拒绝模板

```
【拒绝】结束赛事前置不满足
当前数据不是合法最终快照：
  - Beta 的阶段/血量不一致
  - Gamma 名次与进度冲突
下一步：先用战况域修正上述队伍，再重新结束。
```
